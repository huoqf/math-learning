## 三、P0 级缺陷（数学错误，必须修）

### P0-1 动点页漏掉第三类展开路径 ⇒ `L_min` 最小值算错，且路径命名与几何不符

- **位置**：`src/math3d/parametricPoint.ts:311-322`（真实现）；文案 `src/data/builders/solidParametricPoint.ts:417-440`
- **现象**：
  ```
  :313  // 路径 1 (侧面展开 ABB1A1 + BCC1B1): A(0,0) -> C1(a+b, c)
  :314  const path1Length = Math.sqrt((a + b) ** 2 + c ** 2);
  :318  // 路径 2 (底侧展开 ABCD + BCC1B1): A(0,0) -> C1(a, b+c)
  :319  const path2Length = Math.sqrt(a ** 2 + (b + c) ** 2);
  :321  const globalMinLength = Math.min(path1Length, path2Length);
  ```
  builder `:419` 更把自己的口径写死为结论：「长方体从 A 到相对顶点 C₁ 存在**两种**本质不同的相交平面展开方式」，`:421` 的 rubric 写「**分类讨论所有**可能的平面展开途径」。
- **验算（长方体 A→C₁ 表面最短路径的完整候选集）**：把两相邻面沿公共棱展平，要求展开后的线段真的跨越该棱（否则展平无效）。可达棱共 4 条，去重后得**三类**：

  | 展开所跨的棱 | 展平后 C₁ 的坐标 | 候选长度 |
  |---|---|---|
  | 棱 BB₁ | (a+b, c) | √((a+b)²+c²) |
  | 棱 BC | (a+c, b) | **√((a+c)²+b²)** ← **缺失** |
  | 棱 DC | (a, b+c) | √(a²+(b+c)²) |

  立方体（a=b=c）三式同为 √5a，所以**只在长方体且三边不等时暴露**。
- **反例（参数域内，`solidParametricMeta` 为 a∈[2,6]、b∈[1,5]、c∈[1,5]）**：取 a=2, b=5, c=1
  - 代码：`min(√(49+1), √(4+36)) = min(7.071, 6.325) = **6.325**`
  - 真值：`min(7.071, √((2+1)²+5²)=√34=**5.831**, √(4+36)=6.325) = **5.831**`
  - **误差 0.494（7.8%）**，且面板上 `L_min` 与 `路径 2` 会输出同一个错值。

- **附带错误（同一处）**：`:318` 注释与他人转述把 `√(a²+(b+c)²)` 标成「ABCD + BCC₁B₁（经过棱 **BC**）」，但按上面的坐标推导，`(a, b+c)` 对应的是**跨棱 DC**（即 ABCD + DCC₁D₁）。真正"经过棱 BC"的恰好就是被漏掉的那一类。
- **修法建议（最小改动）**：`math3d/parametricPoint.ts` 增加第三个候选 `path3Length = Math.sqrt((a + c) ** 2 + b ** 2)`，`globalMinLength` 取三者最小值，同时把 `bestPathType` 扩成三态；builder 文案把「两种」改为「三种（跨棱 BB₁ / BC / DC）」，并把两处路径注释与几何对正。新增/修改后请在 `src/math3d/__tests__` 里补 a=2,b=5,c=1 的断言（当前无任何用例覆盖该分支）。

### P0-2 线面页「高考得分点」写错法向量，配套判据是假命题

- **位置**：`src/data/builders/solidLinePlane.ts:79-83`（`gaokaoPoints`）
- **原文**：「【向量建系得分点】以 A 为原点，AB, AD, AP 为 x, y, z 轴建立空间直角坐标系，求出面 PAD 法向量 **n=(0,1,0)**，计算向量 EF·n = 0 即可向量法获满分。」
- **验算**：`math3d/lineRelation.ts:126-130` 给出的顶点为 A(0,0,0)、B(a,0,0)、C(a,b,0)、D(0,b,0)、P(0,0,h)，其中 A、D、P 的 x 坐标**全为 0** ⇒ 平面 PAD 就是 `x = 0`，其法向量为 **(1,0,0)**。`(0,1,0)` 是平面 **PAB**（y=0）的法向量——面名写错。
- **反例**：取默认 a=4, b=3, h=3.5, λ_E=λ_F=0.5 ⇒ E=(2, 0, 1.75)、F=(2, 1.5, 1.75)、EF=(0, 1.5, 0)，
  - `EF · (0,1,0) = 1.5 ≠ 0` ⇒ 按页面给的方法**算不出 0**，学生照着做会卡死；
  - `EF · (1,0,0) = 0` ✓ 才是正确的满分路径。
- **危害**：这是**写在「高考得分点」里的教学错误**，且页面的核心考点就是"线面平行"的向量证明，学生按错法向量建系必然出错。
- **修法建议（最小改动）**：`n=(0,1,0)` → `n=(1,0,0)`，并把措辞改为「求出平面 PAD（即面 x=0）的法向量 n=(1,0,0)」。同页 `:79` 的三步书写法（面外/面内）表述正确，无需动。

### P0-3 进阶球「面面垂直双外心」：右屏用原始参数重算 ⇒ 与中屏数值分裂，并打印**假等式**

- **位置**：`src/data/builders/solidAdvancedSphere.ts:33-41`（另 `:106-118` 的 step3 latex）

  :34  const res = calculatePerpPlanesSphere(r1, r2, c);   // ← math 层内部会 clamp

  而 `src/math3d/advancedSphereModels.ts:43-46` 会钳制：`maxC = 2·min(r1,r2) − 0.05`、`safeC = min(max(0.5,c), maxC)`。
- **反例（滑块域内：`advancedSphereMeta` r1,r2∈[1,6]、c∈[0.5,6]）**：r1=r2=**2**, c=**10**

  - 页面仅在 `:128` 给一条 warning（「接近外接圆直径…极限临界」），**不消除错误数值也不消除假等式**。
- **同类（第二处）**：`:210` 圆台球心距 `d = (h² + r₁² − r₂²)/(2h)` 用**原始** r₂，而 `advancedSphereModels.ts:198` 会把 r₂ 静默抬到 `max(r₁+0.1, r₂)`。取 r₁=3, r₂=1, h=4.24：右屏 d = **3.06**、math 层 d = **2.05**，相差 49%。
- **修法建议**：右屏一律改用 `res` 返回的 `d1/d2/r1/r2/c`（math 层已是 SSOT），`R²` 等式用 `res` 的钳制值拼装；钳制真的发生时，输出一条「参数已被约束到合法域（c 已夹紧为 x.xx）」提示，而不是照抄原始值。

### P0-4 内切球：画出的「半径」比球半径长 50%，且 6 个"切点"中有 2 个不在球面上（**默认参数即触发**）

  ```
  tBottom=(a/2, b/2, 0)  tTop=(a/2, b/2, c)
  tFront =(a,   b/2, c/2)  tBack =(0, b/2, c/2)     ← 这两个不在球面上
  tRight =(a/2, b,   c/2)  tLeft =(a/2, 0, c/2)
  ```
  渲染侧 `:286-287` 用 `filter(([k]) => k.startsWith("t"))` 把**全部 6 个**都标成切点 `T`；`:297` 又把 `auxSegments`（`center→tBottom/tTop/tFront/tRight`，label 全写 `r`）画成"半径"。
- **验算（注册表默认 a=3, b=2, c=2，`circumInSphereMeta`）**：r = 2/2 = **1**，球心 (1.5, 1, 1)
  - `|center − tFront| = |(3,1,1) − (1.5,1,1)| = **1.5** > r = 1` ✗ —— 面板上会出现一条**长度 1.5 的线段标着"r"**，而画出的球半径只有 1 ⇒ 线"戳出球外"；

- **修法建议**：把切点按"到球心距离 = r 的方向"生成（对 `min` 达到的面取垂足，其余面不生成切点），或至少把 `tFront/tBack` 从切点集合中剔除、`auxSegments` 只保留真实切点的连线。三棱柱（`:227,232`）与圆柱（`:364`）分支同型问题需一并处理。
