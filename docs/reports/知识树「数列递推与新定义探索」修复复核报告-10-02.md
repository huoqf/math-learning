**一致性依据**：`d=0` 且 `a1<0`（递减，取 n=1）、`q<1` 单调递减（取 n=1）两处既有约定都是「边界最值取 n=1」，`a1=1,q=1` 的并列最值归入同一约定，口径统一。

### 10.3 P2c 扩测暴露的 2 处**真实越界缺陷**（已修，有实证）

网格一经铺开，立刻抓出两处此前从未被发现的越界 —— 这正是 §9.8 所说「门禁盲区」的价值兑现。

**新-① 矩形最小高度顶出画布**（`rect`，纵向）

| 阶段 | 实测（`a1=0, d=2, q=3, N=8`） |
|---|---|
| 修复前 | `y=649.98, h=2.00` → 底边 **651.98 > 650**（超 1.98 设计单位） |
| 修复后 | `y=648.00, h=2.00` → 底边 **650.00** ✅ |
| 真实浏览器复核 | `rect 设计纵向=[23.18, **650.00**]` ✅ |

> 根因：`y = topY` 与 `height = Math.max(minH, botY−topY)` **各自独立**，当 `botY−topY < minH` 且 `topY` 已贴近底边时，最小高度把底边顶出画布。
> 根治：`fitVertical` 先定 `height`，再 `y = Math.min(topY, 650 − height)`，**数学上保证** `y+height ≤ 650` 且 `y ≥ 0`（`topY ≥ 0`、`botY ≤ 650` ⇒ `height ≤ 650`）。

**新-② 文本 y 未钳制**（`text`，纵向）

| 阶段 | 实测 |
|---|---|
| 修复前 | `tail-warning-term` 的「(必带负号)」`y = yZero + 18 = **667.98 > 665**`（契约允许 `650+15`） |
| 修复后 | 全网格越界文本数 = **0** ✅ |

> 根因：同组另一文本用了 `Math.min(650−12, ptZero.y+16)`，**这一条漏了钳制**（同族不一致）。
> 修复：按同组既有 idiom 对齐为 `Math.min(CANVAS_PRESETS.full.height − 12, mathZero.y + 18)`。

### 10.4 新增 P1：`CoordinateGrid` 刻度数随视口跨度线性膨胀 → 页面卡死（**待用户决策，未改**）

这是本轮**最有价值的发现**，严重度高于 3 条 P2（页面不可用，而非 2px 溢出）。

**机理**：`src/components/Math/CoordinateGrid.tsx` 的 `xStep/yStep` **默认 1**，刻度循环为 `for (y = yStart; y <= yEnd; y += yStep)` ⇒ **网格线数量 ≈ 值域跨度**。而 `ModelsPage` 的 arith-geo 分支 yRange **无上限钳制**。

**归因**：属**既有隐患**（`yRange` 一直无上限钳制），非本轮修复引入。但第三轮把该行由

### 10.6 复核方法论（本轮新增，值得沉淀）

1. **面板内子元素会被误认成面板**：`rightText()` 取「最高且宽 250–420」的 div，实际取到了 MathPanel **内部**的子 div（w=295），真正面板 w=320 ⇒ 误报「右屏无此字段」。**选面板必须加宽度下界**。
2. **设计坐标换算必须同时扣除 `translate`**：`<g transform="translate(0 1.2857) scale(1.5714)">` ⇒ 只除 `scale` 会恒定多出 `ty/sc = 0.82` 设计单位，本轮的「0.82 越界」即此假象；扣掉后 `rect` 底边**恰为 650.00**。
3. **滑块 step 会量化测试参数**：a1 滑块 `step=0.5` ⇒ 探针写 `0.25` 实为 `0.5`；`q=3` 在求和模型页**根本不可达**（`max=2`）⇒ 用不可达参数写用例会既测不到真实风险、又制造病态视口（正是 10.4 卡死被触发的入口）。
4. **单用例内多次 `render` 必须 `cleanup()`**：否则 worker 内存溢出，表现为「测试超时」或「Worker exited unexpectedly」，极易误判为业务缺陷。
