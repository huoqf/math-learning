## 二、遗留1 核对详情

### 1. 关键实现事实：`responsive={false}` 让 block 模式失去拆行与缩放

`MathInvariantsSection.tsx` 的写法是：

```tsx
mode={isWide ? "block" : "inline"}
responsive={!isWide}
```

而 `KatexFormula.tsx` 第 155–158 行：

```ts
if (!responsive || !outerRef.current || !inner) {
  setScale(1);
  return;          // ← 测量 / 语义拆行 / 兜底缩放 全部跳过
}
```

因此 `isWide` 为真时，**语义拆行（`findOptimalSplit`）与兜底缩放都不会执行**。`lines` 只由另一个 effect 通过 `extractLatexLines` 填充，而它**只解构原生多行**（顶层 `\\`），不做任何最优断行。

**直接证据**：`/nike-shifted` 的「渐近线方程」value 是一条 282px 的自然宽公式：

```
x = 1.0, \; y = 1.0x + 1.0 \text{（垂直与斜渐近线）}
```

它既没有被在 `,` / `\;` 处拆行，也没有被缩放，而是被 value 行的 `overflow-hidden` 裁掉了左侧 **5px** —— 截图肉眼可见开头的 `x` 被切掉（见 `scripts/shots/nike-shifted-panel.png`，该卡片渲染为 `= 1.0, y = 1.0x + 1.0 （垂直与斜渐近线）`）。

这与代码注释「使用整行约 280px 宽度 **+ 拆行能力**」直接矛盾。

### 2. 该裁切是**既有**缺陷，不是本次引入 —— A/B 实测

| 状态 | 配置 | `/nike-shifted` value 行宽 | 公式宽 | 左裁 | 右裁 |
|---|---|---|---|---|---|
| 基线（临时还原） | `mode="inline"` + `responsive={true}` | 277px | 282px | **7px** | -2px |
| 当前（遗留1 之后） | `mode="block"` + `responsive={false}` | 277px | 282px | **5px** | 0 |

基线同样裁切，且更重。**根因是既有盲区**：`containerWidth` 取的是

```ts
Math.min(outerRef.current.clientWidth || parent.clientWidth, parent.clientWidth)
```

其中 `parent` 是 value 的 `<span className="font-bold text-xs">`。它作为 `justify-end` 弹性项目带 `min-width:auto`，会随内容撑到 282px —— 于是「容器宽 = 内容宽」，缩放条件 `contentWidth > containerWidth` 永不成立，**兜底缩放永不触发**，最终由外层 `overflow-hidden` 裁掉。基线 7px、当前 5px，两者都是这个盲区的表现。

> 据此修正上一轮报告的一处结论：上一轮报告写「公式裁切 3 → 0、最大溢出 0」。当时的探测脚本以 **KaTeX 组件自身的 `overflow-x-clip` 容器**为参照，存在盲区 —— 组件外框在 block 模式下会随内容变宽，公式超出「value 行」时以组件外框为参照就测不出来。以 **value 行**为参照重新全量探测（新增 `scripts/audit-value-clip.mjs`），发现 **1 处**。修正口径后应为：上一轮修复把裁切从 **3 处降到 1 处**，而非 0 处。

### 3. 两处注释与实际行为不符

**（a）「短公式（单列）保持 inline 行内排版」不成立。**
判据是**卡片级** `isWide`：

```ts
const isWide = isLongSymbol || isLongValue || q.label.length > 8;
```

只要**卡片**被判定为宽卡（例如 `label` 超过 8 字、或 `symbol` 太长），卡内**很短**的 value 也会走 block。全量统计证实：**137 条 value 公式中 123 条为 displayMode**（覆盖 46 条路由）。典型如：

```
/sequence-arithmetic   x_0 = 2      S_6 = -9      a_6 = -4
/trig-transform        π           -1.50         4 + 5i
/function-power        y = x^2
```

**（b）「拆行能力」不成立。** 见 §二.1。

### 4. 外观影响（非缺陷，但需知悉）

- **位置未变**：value 仍右对齐（实测 `右距 = 0`），数值与单位仍在同一行。
- **样式变了**：display 模式令 `\displaystyle` 生效。普通公式与数值几乎无差别；但含 `\lim` / `\sum` / `\int` 的 value（如 `/probability-markov` 的 `t = \lim_{n\to\infty} p_n`）会把上下限从右下角改为**正上/正下方**，行高略增。数学上更贴近教材，属可接受的外观变化。
- `src/index.css` 已有 `.katex-display { margin: 0 !important; }`，因此 display 模式默认的 `1em` 上下边距已被消除，**没有出现竖向膨胀**。

### 5. 目标未达成的原因

触底缩放全量 **55 → 55**。被改的这 123 条 value 公式**本来就不是**触底缩放的来源（抽样实测其 `scale` 均为 1）。真正贡献触底缩放的是**其他分区与组件**：

| 路由 | 触底缩放数 |
|---|---|
| `/probability-markov` | 6 |
| `/constant-double` | 5 |
| `/derivative-shift` | 4 |
| `/complex-geometric`、`/derivative-monotonicity`、`/derivative-inflection`、`/paired-data-regression` | 各 3 |

也就是说：**遗留1 选择的切入点与实际的缩放瓶颈不重合**。

## 三、遗留3 核对详情

### 1. 布局安全（12 条 3D 路由全量实测）

新增的包装层 `<div style={{ width: "100%", height: "100%" }}>` 在全部 12 条 3D 路由上均正确解析：

| 路由 | canvas | ThreeDCanvas 根 | 包装层高 | 父级 |
|---|---|---|---|---|
| `/solid-angle` | 1000×844 | 1000×844 | 844px | `.w-full.h-full.relative`（844px） |
| `/solid-distance` | 1000×844 | 1000×844 | 844px | `.flex-1.relative`（844px） |
| `/vector3d-basis` | 1000×844 | 1000×844 | 844px | `.flex-1.bg-white.overflow-hidden`（844px） |
| 其余 9 条 | 1000×844 | 1000×844 | 844px | 同上两类 |

**无塌陷（0 条画布高为 0）、无尺寸变化、无位移。**

⚠️ 但该安全性**依赖父级链上有确定高度**（`flex-1` / `h-full`）。若将来某路由把 `ThreeDCanvas` 放进高度为 `auto` 的容器，`height:100%` 会退化为 `auto` → 画布塌陷为 0 高。建议把包装层改为 `className="w-full h-full"`（Tailwind 的 `h-full` 同样依赖父级高度），或更彻底地用 `display: contents` 让包装层不参与布局，从根本上消除这层耦合。

### 2. 行为验证（单元级，4 项全跑）

| # | 场景 | 结果 |
|---|---|---|
| 1 | render 阶段抛错 1 次 | ✅ 最终正常渲染；无降级文案 |
| 2 | **effect 阶段抛错 1 次**（模拟卸载竞态） | ✅ **被捕获、自动重建、正常渲染；`console.warn` 恰好 1 次** |
| 3 | 持续抛错 | ✅ 展示降级 UI，且自动重建**只发生 1 次**（`warn` 仍为 1 次）→ 无死循环 |

结论：**「首次自动重建、二次降级」的策略实现正确，且能兜住 effect 阶段的错误**。

### 3. 对目标错误未见实效

在**无并发负载**的干净全量扫描中，`/solid-parametric` 依旧报出：

```
Cannot read properties of null (reading 'addEventListener')
```

且**仍以 `pageerror` 形式逃逸**（`pageErrors = 1`）。这说明该错误的抛出时机**不在 ErrorBoundary 能覆盖的阶段**（事件回调 / 异步任务），或不在其子树内 —— 与 §三.2 的第 4 项验证一致：**ErrorBoundary 对事件/异步阶段的错误无能为力**。

代码溯源（`node_modules`）支持这一判断：

| 位置 | 是否可能产生该文案 | 说明 |
|---|---|---|
| `three-stdlib/OrbitControls` `this.connect(domElement2)` | 否（文案不符） | 先执行 `scope.domElement.style.touchAction`，若为空报的是 `.style` |
| `three-stdlib/OrbitControls` `listenToKeyEvents(domElement)` | 是（文案完全一致） | `domElement.addEventListener` 无空值保护；但 drei 与本项目**均未调用** |
| R3F `addEvents(target)` 内 `target.addEventListener(...)` | **是** | `connect()` 时若 `target` 为 `null` 即抛此文案 —— **最可疑来源** |
| 本项目自有代码 | 否 | 全库仅 4 处 `addEventListener`，全部挂在 `window` 上（永不空） |

`R3F` 的 `connect/connectXREvents` 由 `<Canvas>` 的 effect 与其内部事件系统驱动，**部分路径在事件/异步阶段**，因此边界拦不住是符合预期的。

### 4. 可观测性退化（本次改动最需要关注的副作用）

两个问题叠加：

1. **丢失堆栈**：`componentDidCatch` 目前只输出 `error.message`：
   ```ts
   console.warn("[Canvas3DErrorBoundary] 检测到 3D 画布竞态崩溃，自动重建：", error.message);
   ```
   没有 `error.stack`，就**永远无法定位到具体文件与行号**。这正是这个偶发问题从审查阶段拖到现在仍未定论的原因。
2. **审计失明**：我们的检测手段依赖 Playwright 的 `pageerror`。一旦错误被边界捕获（例如落在 effect 阶段），它就不再是 pageerror —— **审计将报告"干净"，但问题可能仍在发生**。本次干净扫描中 `/solid-parametric` 仍报 pageerror，说明这一次没被捕获；但下一次若落在 effect 阶段被捕获，我们就再也看不到它了。

因此，遗留3 当前的净效果是：**可能减少了用户可见的崩溃，但同时切断了我们继续追查它的证据链**。

### 5. 降级文案的一帧提交

`getDerivedStateFromError` 先返回 `{ crashed: true }` → 渲染降级文案并提交 → `componentDidCatch` 再 `setState` 重建。降级文案会被提交到 DOM 一次。两次提交在同一任务内完成，通常**不会绘制出可见闪烁**；若要绝对稳妥，可在「自动重建那一次」渲染 `null` 而不是提示文案。

## 六、建议的修改方案（尚未改动代码）

### 针对 P1 —— `/nike-shifted` 公式被裁 5px（既有缺陷，建议本轮一并修掉）

**根因**：`containerWidth` 取的是会随内容撑大的 `<span>`（`min-width:auto`），使缩放条件永不成立。

**方案（两处小改，选一即可，推荐 A）**
- **A**：给 value 的 `<span>` 加 `min-w-0`（`className="font-bold text-xs min-w-0"`）。使该弹性项目可收缩到行宽，`containerWidth` 随即等于真实可用宽度 277px，兜底缩放（scale≈0.968）正常触发，公式完整显示且字号几乎无损。**最小改动、对症。**
- **B**：在 `KatexFormula` 内把可容纳宽度改为「向上找到第一个 `overflow-x ≠ visible` 的祖先」的 `clientWidth`，从组件层面彻底消除该盲区（影响面更大，需回归全部 2041 条公式）。

### 针对遗留1 —— 建议调整（否则注释与行为长期不一致）

1. **去掉 `responsive={false}`**（改为默认 `true`）。block 模式由此真正获得「语义拆行 + 兜底缩放」，与注释一致；`canLineBreak = isBlock` 自然会生效。
2. **把触发条件从"卡片级 `isWide`"改为"value 自然宽度超过行宽"**。这样 `x_0 = 2`、`π`、`4+5i` 这类短 value 回到 inline，避免 123 条公式无谓地切换 display 样式；只有真正放不下的长 value 才升 block。
3. 若 1、2 都采纳，建议再做一次全量扫描确认「触底缩放」是否真的下降；若目标本就是降触底缩放，应把精力投向 `/probability-markov`、`/constant-double`、`/derivative-shift` 等真实来源。
4. 若决定保留现状，请**修正注释**，避免后续维护者被误导。

### 针对遗留3 —— 建议补两点

1. **记录完整堆栈**（关键，成本极低）：
   ```ts
   console.error("[Canvas3DErrorBoundary] 3D 画布崩溃，自动重建：", error);
   ```
   下一次出现即可直接定位到文件与行号，终结"无法复现"的僵局。同时把审计脚本改为**同时采集 console**，避免被捕获的错误从视野中消失。
2. **包装层改用 `display: contents`（或至少补 `min-h-0` 语义）**，消除 `height:100%` 对父级确定高度的隐式依赖。
