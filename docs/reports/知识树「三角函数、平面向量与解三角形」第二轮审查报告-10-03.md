### P0-1 ★★★ `triangleSolve` 的 SSA 场景把 ∠A 的内角弧画在底边的**镜像侧**

- **位置**：`src/features/triangleSolve/components/TriangleSolveSsaScene.tsx:100-117`（角弧路径）、`:119-120`（「60°」标注）

```tsx
pA = mathToDesign(pointA.x, pointA.y, scale); // :28  设计坐标（y 向下）
radA = (angleA * Math.PI) / 180; // :32  数学角
const startX = pA.x + arcR;
const startY = pA.y; // :103-104  沿底边 AC
const endX = pA.x + arcR * Math.cos(radA);
const endY = pA.y + arcR * Math.sin(radA); // :105-106 ← 直接把数学角的 sin 加进设计 y
```

**验算**（探针直跑 `math/triangleSolve.ts`）：`solveSSA(4.5, 5, 60)` →

```
A = (-5, 0)   C = (0, 0)    ⇒ 底边 AC 沿数学 +x、与设计 +x 同向
solutions = [(-3.1376, 3.2257), (-4.3624, 1.1044)]   两个顶点 B 都在底边【上方】(y>0)
pRayEnd = mathToDesign(-5 + 12·cos60°, 12·sin60°) = (-5 + 6, +10.392)  ⇒ 屏幕【右上方】✔

```

同位对照：同页 `TriangleSolveScene.tsx:189-201` 的角弧用 `Math.atan2(dirAB.y, dirAB.x)`（**从设计坐标取方向**）⇒ 结论正确。SSA 场景漏了这一次 y 翻转。

- **后果**：屏幕上三角形的内角弧与「60°」标注**整体落在底边之下**，即画在了 ∠A 的**外角位置**。学生看到的是"三角形的角画在三角形外面"。这是本轮唯一"图形与数学事实不符"的硬错误。
- **判定**：**确认错误**（探针复算 + 同页正确写法对照）。
- **修法方向**：改为从设计坐标取方向（与 `TriangleSolveScene` 统一），即
  `const endRad = Math.atan2(-Math.sin(radA), Math.cos(radA))`（或直接用 `pRayEnd` 的方向），标注位置 `:119-120` 同步。

### P0-2 ★★★ `triangleSolve` 顶点 A 的拖拽映射既不互逆、方向还相反（握点即跳变）

三条独立缺陷：

1. **握点即跳变**：默认 A=60°，只要按下顶点 A 不动，映射就把它改成 **77°**。
2. **方向相反**：A > ~30° 区间内 A↑ ⇒ 顶点 y↓，而映射随 y↓给出**更小**的 rawAngle ⇒ **把顶点往上拖反而让 A 变小**，与几何直觉相反（且映射在 A≈30° 处自身非单调）。

- **判定**：**确认错误**（探针复算；`RANGE_ANGLE_A` 钳制只保证不越界，不解决映射本身错）。
- **修法方向**：不要用"纵坐标线性反解角度"这种启发式。应由 `solveTriangleFromSAS` 建一个**单一 SSOT 的逆映射**（给定目标 A 角，用同一份顶点重定公式求 A.y），或直接改为拖拽"顶点 A 在圆上的方位角"并同步 A.y。
