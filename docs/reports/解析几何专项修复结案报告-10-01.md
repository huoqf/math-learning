### 2.8 ｜5.4 分数系数预设（本轮唯一涉及新能力的项）

**前置障碍**（已向用户说明并由用户选定方案）：`formatMathNumber` 只保留两位小数，`2/3` 会印成 `0.67`、`1/9` 印成 `0.11`；而「一般方程配方」题型里系数与圆心半径的真值**本来就是分数**。只加预设不改显示，等于把「分数通分 + 配方」这个考点换成机器近似值。

**新增 SSOT**（`src/utils/mathFormat.ts`，+56 行）

```ts
export function formatMathRational(x, maxDenominator = 100): string | null
export function formatMathRationalOrNumber(x, maxDenominator = 100): string
```

- `formatMathRational`：输出最简分数 LaTeX（`2/3 → \frac{2}{3}`、`-1/3 → -\frac{1}{3}`）；**整数直接返回十进制字符串**（`-4 → "-4"`），故对既有整数参数**零副作用**；无理数返回 `null` 由调用方回退
- `formatMathRationalOrNumber`：分数优先、小数兜底，把「显示策略」也收敛成一处定义
- 与既有 `formatPiFraction` 的分工在 docblock 写明：后者管 π 的分数倍，本函数管纯有理数
- 单测 +6（含「经浮点运算得到的分数仍能识别」与「滑块值 `0.6667` 不得误判为 `2/3`」两条反例守卫）

**新增预设**（`src/data/registries/circleEquation.ts`，2 条，均为 `general` 模式）

| key | 方程 | Δ_c | 圆心 | r |
|---|---|---|---|---|
| `general_frac_coeff`「分数系数·配方典型」 | `x² + y² + \frac{2}{3}x − \frac{4}{3}y + \frac{1}{9} = 0` | `16/9` | `(−1/3, 2/3)` | `2/3` |
| `general_frac_integer_radius`「分数系数·整半径」 | `x² + y² − \frac{4}{3}x + \frac{2}{3}y − \frac{4}{9} = 0` | `4` | `(2/3, −1/3)` | `1` |

两组的 D/E/F、圆心、半径全为分数且**无舍入**（Δ_c 恰好是 `16/9` 与 `4`，r 恰为 `2/3` 与 `1`），配方链条在右屏 3 步 `reasoningSteps` 中完整走通。

**配方第 2 步右端改进**：由 `\frac{\frac{16}{9}}{4}`（嵌套未算完）改为 `\frac{D^2+E^2-4F}{4} = \frac{4}{9}`——这一步的采分点就是算出右端常数。

### 三·2 🔴 `circleEquation` 全页 `toFixed(2)` 浮点尾零（报告 5.3 判为「达标」，判错）

做第 8 项时发现 `src/math/circleEquation.ts` 三条求解函数都在用 `toFixed(2)` / 裸插值生成方程字符串。逐条实测（预设取自 `CIRCLE_EQUATION_PRESETS` 原值）：

| 模式 | 预设 | 修复前屏幕上的字面 | 修复后 |
|---|---|---|---|
| standard | `standard_origin`（**默认预设**） | `x^2 + y^2 - 9.00 = 0` | `x^2 + y^2 - 9 = 0` |
| standard | `point_inside` | `x^2 + y^2 - 2x - 2y - 7.00 = 0` | `… - 7 = 0` |
| standard | `point_on` | `x^2 + y^2 - 25.00 = 0` | `… - 25 = 0` |
| threePoints | `three_unit` | `x^2 + y^2 = 1.00` / `… - 1.00 = 0` | `= 1` / `- 1 = 0` |
| threePoints | `three_rt_triangle` | `x^2 + y^2 = 9.00` | `= 9` |
| threePoints | `three_general`（标称「高考真题一般三点」） | `(x - 4.00)^2 + (y - 1.00)^2 = 5.00`、`x^2 + y^2 - 8.00x - 2.00y + 12.00 = 0` | `(x - 4)^2 + (y - 1)^2 = 5`、`x^2 + y^2 - 8x - 2y + 12 = 0` |

即：**新页三种模式的每一条既有预设，在屏幕上都有浮点尾零**，`threePoints` 连一次项系数都印成 `- 8.00x`。这属项目明令禁止的「工科测量机器浮点尾零」。

**处置**（与第 8 项同一缺陷类，按用户「反对拆东墙补西墙」的一贯要求一并关闭）：

| 函数 | 处置 |
|---|---|
| `solveGeneralCircle` | 系数 / 圆心 / 半径 / 方程字符串走 `formatMathRationalOrNumber`；新增 `quadraticParts(a, b)` 复用于有效支与退化支 |
| `solveStandardCircle` | 常数项 `fStr` 与 `rSqStr` 改走 SSOT（`a,b,r` 是滑块选定的几何量，故用**小数**而非分数，仅去掉尾零） |
| `solveThreePointsCircle` | D/E/F 与外心、半径走 `formatMathRationalOrNumber`（待定系数法的解本就是分数形态） |
| 退化支 | `(x - (-2.00))^2 + (y - (3.00))^2 = 0` → `(x + 2)^2 + (y - 3)^2 = 0`（去掉双层括号与裸数值） |

**回归守卫**：`src/math/circleEquation.test.ts` +2（`7` 用例）——逐字断言三种模式的修复后字符串，含三点式分数解 `x^2 + y^2 - \frac{5}{3}x - \frac{7}{3}y + \frac{2}{3} = 0`。

**更正说明**：第二轮报告 5.3 节写「教学与规范 ✅ 达标」——该结论**过度乐观**。当时核对的是数学正确性与契约（`MathQuantity` 用 `cx/cy` 等），未逐字检查方程字符串的格式化，漏掉了这条贯穿三种模式的规范缺陷。已在第四节记录为方法论教训。

# prettier：必须剥离 CR 后再比对，否则 core.autocrlf 会污染结果。
# 注意：git 默认会对非 ASCII 路径加引号并转义成八进制，必须用 core.quotepath=false，
#       否则中文名文件会被静默跳过（本报告第一版就踩了这个坑）。
git -c core.quotepath=false status --porcelain | cut -c4- | while IFS= read -r f; do
  case "$f" in *.ts|*.tsx|*.json)
    [ -f "$f" ] && diff <(tr -d '\r' < "$f") <(npx prettier "$f" | tr -d '\r') | grep -c '^[<>]'
  ;; esac
done                                                      # 全部 0

# 行尾判定必须用 od -c（Git Bash 下 grep -c $'\r' 结果不可信）
head -c 60 <file> | od -c
