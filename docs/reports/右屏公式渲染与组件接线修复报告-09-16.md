## 二、P0 级修复详述

### A. `examAnchor` 徽标越界（8 条路由）

**现象**：右屏首行「图标 + 标题 + 题型定位徽标」三件套挤在 295px 内容宽内。徽标带 `shrink-0`，既不收缩也不换行、不省略，实测宽度 301~340px，越界 6~45px；其中 `/function-zero`(+45px)、`/conic-line`(+25px)、`/derivative-monotonicity`(+20px) 三条使右屏容器真的产生水平溢出（`scrollWidth 352 > clientWidth 319`），其余 5 条被根节点 `overflow-x-hidden` 静默裁成半句话。

**修复**：采用审查报告中的**结构性方案**（选项 3），而非「让徽标参与收缩 + truncate」。

```
修复前：[图标] 标题（可省略）           [★ 题型定位徽标 shrink-0 不换行 ← 越界]
修复后：[图标] 标题（可省略，补 title 完整文案）
        [★ 题型定位徽标 · 独占一行 · 自然换行 · leading-snug · 补 title]
```

**为什么不选「让徽标参与收缩 + truncate」**：徽标承载的是题型定位信息（如「人教A版必修第一册 · 函数与方程及二分法 (必考基础/解答通法)」），截断即信息丢失，只是把越界换成了不可读。独占一行同时解决越界与长文案可读性，且不影响标题区。

**同时补上**：标题与徽标都加 `title` 属性，鼠标悬停可看完整文案。无徽标时的「数学解析看板」兜底文案逻辑保持不变。

### B. 公式被永久裁切（3 条路由）

**现象**

| 路由 | 模式 | 容器宽 | 内容自然宽 | 实际缩放 | 越界量 |
|---|---|---|---|---|---|
| `/probability-markov` | inline | 221px | 647px | 0.65（触底线） | **+100px** |
| `/solid-angle` | block | 243px | 593px | 0.55（触底线） | **+83px** |
| `/inequality-absolute` | inline | 249px | 412px | 0.65（触底线） | **+9px** |

**根因（三者同一）**：`KatexFormula` 的 `const nextScale = Math.max(minScale, needed)` 把缩放**硬夹**在下限。行内模式下限 0.65 ⇒ 公式绝对上限只有容器的 1/0.65 ≈ **1.54 倍**；块级 0.55 ⇒ **1.82 倍**。三条样本又恰好都无法语义拆行：`/solid-angle` 是一条整句塞进单个 `\text{}` 的中文长句（全角逗号在 `\text{}` 括号内、非顶层，拆行算法找不到断点）；另外两条是行内模式，而行内模式**严格禁止断行**（设计如此）。

**修复（四个层面同时下手）**

1. **拆出独立常量**：`HARD_MIN_SCALE = 0.55`（已允许拆行时）与 `INLINE_MIN_SCALE = 0.65`（行内）分列，语义从「魔法数字」变为明确的双阈值。

2. **新增行内降级通道**（核心修法）：把「行内严格不许断行」从硬约束降级为「优先不断行」。当行内公式在 0.65 硬底线下依然放不下时，转入可拆行排版（保持行内流，多行堆叠），从**结构上**消灭「缩到硬底线仍被裁掉两端」。

   ```ts
   const shouldDegrade =
     !canLineBreak &&
     naturalWidth > 0 &&
     (containerWidth - 4) / naturalWidth < INLINE_MIN_SCALE;
   const breakable = canLineBreak || lines !== null || shouldDegrade;
   ```

3. **裁决必须是「纯函数」**（关键设计约束，避免死循环）：若按「容器宽度是否变化」决定降级/回退，会与滚动条的出现/消失形成 setState 循环 —— 滚动条出现 → 容器变窄 → 降级 → 内容变矮 → 滚动条消失 → 容器变宽 → 回退 → …。故裁决只依赖「公式自然宽度 + 当前容器宽度」，并用 `naturalWidthRef` 缓存**与容器宽度解耦**的自然宽度（取历史最大值防空测量抖动，公式变更时作废）。

4. **把静默截断变成显式信号**：`nextScale > needed` 时在 `import.meta.env.DEV` 下 `console.warn` 公式宽度、容器宽度与剩余裁切量。今后同类问题会在开发期直接暴露，而不是等学生看到半条公式。

5. **数据侧兜底**：`builders/solidSpatialAngle.ts` 那条整句 `\text{}` 在「条件」与「结论」之间补一个**顶层** `\;` 语义间距断点，为拆行算法提供合法断点，**内容与标点完全保留**（仅新增一个语义间距）。

6. **字体就绪复测**：KaTeX 用 woff2 字体，字形异步换入后内容宽度会变化。若首次测量发生在换入之前，缩放比会偏大、留下几像素溢出且**不会自愈**。现在在下一帧（`requestAnimationFrame`）与 `document.fonts.ready` 后各补测一次，保证「测量-缩放」与最终排版一致（含 `cancelled` / `cancelAnimationFrame` 清理，避免卸载后 setState）。

## 三、P1 / P2 级修复详述

### C + G. 数据链路漏传 → 整包透传（根因消除）

**现象**：`/function-symmetry`、`/nike-standard`、`/nike-amgm`（漏 `reasoningSteps`）、`/solid-angle`（漏 `examAnchor` + `mnemonic`）——同一个 builder，只因页面逐项枚举传参的清单不同，整个教学分区就不渲染。

**修复**：不做「逐个补参数」的补丁，而是**从结构上消灭 C 类缺陷**——全库调用点统一为整包透传：

```tsx
// 修复前（82 个调用点中 53 个长这样，漏一个字段即静默丢失一个分区）
<MathPanel quantities={...} theorems={...} warnings={...} reasoningSteps={...}
           gaokaoPoints={...} examAnchor={...} mnemonic={...} />

// 修复后（全部调用点）
<MathPanel {...mathPanelData} title="…" />
```

**语义安全依据**：`MathPanelData`（`src/data/types.ts`）与 `MathPanelProps` 字段名完全一致，展开语义安全；`title` 不在 `mathData` 中，写在展开运算符之后覆盖顺序天然正确。

**改造范围核对**：全库扫描 `{...mathPanelData}` / `{...mathData}` 命中 **82 个调用点**；仍逐项枚举的只剩 **1 处，即 `MathPanel.tsx` 自身内部调用 `MathInvariantsSection`**（组件定义，不是右屏调用点）。已批量改造脚本化，避免手改遗漏。

**验证**：分区总数 331 → **335**，缺失分区的 4 条路由全部补齐。

### D. 拆行算法两处缺陷

**D-1 `\;` 的分号被当成顶层断点 → 产生非法 LaTeX**

候选扫描只看字符、不看前缀：`if (isTopLevel(state) && (latex[i] === "," || latex[i] === ";"))`。实测 `\alpha \subset \beta, \; \alpha \cap \beta = l` 被拆成 `["\alpha \subset \beta, \", "\alpha \cap \beta = l"]` —— 左行以**孤立反斜杠**结尾，是非法 LaTeX，KaTeX 在 `throwOnError:false` 下会把它渲染成红色错误文本。

修法：`\,` `\;` `\!` 等是 LaTeX 间距命令，末尾的 `,` / `;` 属于命令名的一部分，加反斜杠前缀判断排除。

**D-2 断点标点被直接删除 → 公式内容被静默改写**

`latex.slice(0, chosenIdx)` 会丢掉断点处的标点，例如 `x_1 = 1, x_2 = 2, x_3 = 3` 被拆成 `x_1 = 1, x_2` / `= 2, x_3 = 3`，`x_2` 与 `= 2` 之间的逗号消失。这是**内容级变更**，不是排版选择。

修法：断点标点保留在**左行行尾**（符合「逗号留在上一行」的教材习惯），右行从 `chosenIdx + 1` 起；同时清理右行行首残留的 `\;` `\,` `\quad` `\qquad` 等间距命令，避免续行无故缩进。

### E. 续行悬挂对齐

**现象**：拆行算法把 `=` `+` 等符号放到续行行首（这符合人教版教材习惯，是对的），但所有行都从同一左边界起排，续行的 `=` 与首行的 `f` 对齐、而非与首行的 `=` 对齐。

**修复**：不在 `KatexFormula` 里估算字宽推 `paddingLeft`（脆弱），而是用 LaTeX 自己的 `\phantom` 做**真实宽度**占位：

- 新增 `getAlignmentPrefix(line)`：取首行中「首个顶层关系符 / 推导符 / 变换箭头」之前的片段作为占位基准。含 `\begin{` 或有效长度 > 12 时返回 `null` 退回左对齐——`\phantom` 不允许承载环境体，过长的前缀也会挤占本就只有 295px 的行宽。
- 新增 `startsWithRelation(line)`：只有「以关系符 / 二元运算符 / 变换箭头起头」的续行才加占位 —— 这正是教材推导续行的标准形态。

```
修复前：f(x) = a(x - h)² + k
        = a x² - 2ahx + ah² + k        ← 续行 "=" 与首行 "f" 对齐

修复后：f(x) = a(x - h)² + k
              = a x² - 2ahx + ah² + k  ← 续行 "=" 与首行 "=" 纵向对齐
```

**关键约束（必须守门）**：占位**仅对「引擎自动语义拆行」产生的多行生效**。原生 `aligned` / `cases` / `matrix` 等环境由 KaTeX 自身完成列对齐，二次干预会破坏它。用 `hasNativeLineBreaks` 判定并跳过。

### F. `\frac → \dfrac` 作用域

**问题**：`normalizeFractionRowSpacing` 对**所有**模式（含 `mode="inline"`）无条件把 `\frac` 升为 `\dfrac`，行内正文行高会被抬高，与 `overflow-hidden` 组合存在竖向挤压风险。

**修复**：增加 `displayFraction` 参数（默认 `false`），`KatexFormula` 侧暴露 `forceDisplayFraction` prop（默认 `true`）；多行环境（`cases`/`aligned`/`array`）不受该开关影响，始终升级并注入 `0.65em` 行距补偿。

**必须如实说明的一点**：由于 `forceDisplayFraction` 默认为 `true`，而当前**没有调用方显式传 `false`**，因此**线上视觉行为保持不变**（仍沿用既有教学规范：分式统一满字号）。本次交付的是把「全局静默改写」变成「调用方显式声明」的**可声明能力**，而不是已经切换到标准 textstyle。审查报告对该项的判定本来就是「实测竖向裁切 0 处，属规范与风险项」，故不构成缺陷；是否切换到 textstyle 属产品决策，见 §七 遗留 2。

## 四、修复过程中新发现的缺陷（H–K）

这四类问题在修复 A–G 的回归复测中暴露，均**先于本次修复就已存在**，且都直接面向学生可见。

### H. 右屏纯文本数学字段泄漏（P0）

**现象**：右屏的 `label` / `unit` / `value` / `rubric` / `mnemonic` 里含 `$...$` 时被当普通字符串渲染，学生看到字面 `$x_0$`；含 `\color{...}` 时直接看到反斜杠命令。

**泄漏面**：全库实测 **19 / 73 条路由、61 个文本节点**。典型如 `/nike-shifted` 的评分要点「准确写出换元定义域 $u \ne 0$ 得 2 分」。

**修复**

1. `renderMixedLatex` 全面接管这 5 个字段的渲染：按 `$...$` 定界符切分，数学片段交 KaTeX，其余文本走 Fragment 正常换行。
2. `MathInvariantsSection` 的 `value` 分流判据改为 `hasLatex(valStr) && !valStr.includes("$")`。**含 `$` 的串绝不可整串交给 KaTeX** —— 定界符在数学模式中非法，KaTeX 会退回「错误源码」显示，出现红色文本。这是修复过程中踩到并修正的一个坑。
3. 新增 `toPlainMathText()`，专供 `title` / `aria-label` 等**只能承载纯文本**的属性：这些属性不走 KaTeX 渲染，若原样传入，悬停提示里会暴露 `$x_0$`、`\color{...}`。它会剥离 `$`、`\color{}`、`\text{}` 与其余命令。

**验证**：数学标记泄漏 19 → **0** 条路由、61 → **0** 个节点。

### I. `truncate` 容器中的行内公式被压到不可读（P1）

**现象**（在修复 H 时引入的回归，已当场修掉）：`label` / `unit` 位于 `truncate`（单行 + 省略号）容器中。行内公式作为 inline-flex 盒参与行内 fit-content 协商，被剩余空间挤压到几像素宽，自适应缩放随即把公式缩到 0.55~0.625 的硬底线。触底缩放公式数一度从 54 反弹到 **64**。

**修复**：给 `renderMixedLatex` 增加 `responsive` 开关（默认 `true`），`label` / `unit` 传 `{ responsive: false }`。单行省略号场景的正确行为是**保持公式自然字号，由文本省略号负责截断**，完整文案通过 `title`（配合 `toPlainMathText`）提供。

**验证**：触底缩放公式数回落到 **55**。

### J. 数据侧 `$...$` 约定对齐（P2）

`builders/sequence.ts` 3 处 label、`builders/complex.ts` 1 处 unit 原先是**裸 LaTeX**（无 `$` 定界符），只能靠「含反斜杠就整串交给 KaTeX」的启发式识别。统一改为 `$...$` 包裹，让最外层 `$` 由 `renderMixedLatex` 统一切分，路径唯一、行为可预期。

### K. `extractLatexLines` 解构并列多行环境（P0）

**现象**：界面出现**红色 `katex-error` 源码文本**——KaTeX 编译失败，把出错的 LaTeX 原文直出。

**根因**：旧实现用整串首尾正则解包 `aligned` / `gathered`。对**并列环境**：

```
\begin{aligned}…\end{aligned} \\ \begin{aligned}…\end{aligned}
```

首尾虽然匹配，但内部仍留有**完整的第二组环境**。剥掉外层 begin/end 后拍平，就得到「有 `\begin{aligned}` 无 `\end{aligned}`」的非法片段，KaTeX 直接报错。

**修复**：重写为**深度感知**的实现，固化三条不变量（缺一即导致独立成行后 KaTeX 编译失败）：

1. **只在顶层的 `\\` 处切分**。`aligned`/`gathered`/`cases` 等环境内部的 `\\` 是该环境自身的行分隔，必须留在环境体内 —— 否则环境被拦腰截断成两个半截。
2. **`\\` 之后的可选行距参数 `[..]` 一并丢弃**。切出的片段由外层 flex gap 统一控制行距，残留的行距参数在环境外属非法语法。
3. **片段内的顶层 `&` 必须剥离**。顶层 `&` 没有对齐上下文，KaTeX 报 `Expected 'EOF', got '&'`；环境体内的 `&` 位于非顶层，予以保留。

配套新增：

- `unwrapSingleAlignedEnv(latex)`：**严格校验「恰好一对」**（用 `countOccurrences` 计数）才解包。这样既修掉并列环境的缺陷，又**保住既有语义** —— 单独一个 `aligned` / `gathered` 包裹时仍然拍平为多行（这是窄容器中避免整体暴跌字号的必要前提），`formulaQualityAndDisplay.test.ts` 的「正确解构 `\begin{aligned}` 包裹的多行公式」断言不受影响。
- `RIGID_ENV`：含 `cases` / `matrix` / `pmatrix` / `bmatrix` / `vmatrix` / `array` 且**无外层 aligned 可解包**时整体交出，绝不外部切分 —— 这些环境内部的行列结构由 KaTeX 自行负责。

## 五、关键工程决策（记录被否决 / 已回退的方案）

这几条是修复过程中实际走过的弯路，固化下来避免今后复发。

1. **`containerWidth` 改用父容器宽度 —— 已回退。**
   为缓解「行内小公式过度缩放」，曾把可用宽度改为父元素宽度。放宽基准后 `/conic-line` 立刻出现 **3 处真实裁切（9px / 8px / 8px）**。结论：可用宽度必须取「自身盒宽与父级宽度的**较小值**」——自身盒宽在行内上下文中等于裁切宿主的可用宽度，以它为准才能保证「**绝不裁切**」这条硬不变量。该结论已写进代码注释。

2. **行内降级裁决不得依赖「容器宽度变化」这类记忆状态。**
   见 §二 B 第 3 点：会与滚动条的出现/消失形成 setState 死循环。裁决改为只依赖「公式自然宽度 + 当前容器宽度」的纯函数，并缓存自然宽度以解除对测量时序的依赖。

3. **`examAnchor` 不采用「参与收缩 + truncate」。**
   见 §二 A：截断即信息丢失，只是把越界换成不可读。

4. **续行对齐不用估算字宽推 `paddingLeft`。**
   改用 KaTeX 原生 `\phantom` 做真实宽度占位，不依赖字体度量估算。

## 七、遗留与后续建议

1. **55 处触底缩放（`scale < 1`）保留为可接受的降级行为，不是裁切。** 成因是右屏内容宽仅 295px，而部分行内单符号公式（`x_0`、`\vec{s}` 等）位于 `truncate` 容器中。`label` / `unit` 已通过 `responsive: false` 修掉主要来源；`value` 字段仍保留默认 `responsive`。若要让触底数进一步下降，可让 `value` 也改走「自然字号 + 省略号」或把这类单符号公式改为纯文本 + 上标写法。**当前状态不影响公式完整显示**（裁切 0 处）。

2. **`forceDisplayFraction` 目前无调用方传 `false`**，即分式满尺寸的教学规范仍为现状。若后续希望正文行内公式恢复标准 textstyle（减小行高），只需在调用点显式传 `false` —— 能力已就绪，属产品决策而非缺陷。

3. **偶发 `pageerror`（约 1/73 路由次）**：`Cannot read properties of null (reading 'addEventListener')`。归属路由会在**相邻立体几何路由之间漂移**（修复前基线落在 `/solid-distance`，本次复测落在 `/solid-parametric`，二者在路由表中相邻）。定点复测（立体几何 6 条路由 × 3 轮 = 18 次导航）与全量 73 路由两轮独立探针均**0 次复现**。判定为**既有的、与右屏无关的偶发问题**（可疑方向：长会话中 3D / WebGL 组件的上下文或清理竞态）。建议**单独立项排查，不要混入本次右屏修复**。

4. **未路由的聚合页死代码**（`ConstantAnimation`、`FuncExpLogAnimation`、`PairedDataAnimation`、`SetAnimation`、`NikeAnimation`、`SequenceAnimation`、`FuncPropertiesAnimation`）本次已一并同步修复（整包透传），但它们与 `meta.ts` 的 `loader` 已不一致。建议明确「保留并同步」或「删除」，避免下次审查继续产生歧义。
