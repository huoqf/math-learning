## 四、项 ① 2px 容差：达成预期，代价是 5 处亚像素裁切

### 4.1 残留裁切逐处定位（A2 态，73 路由全量）

| 路由 | 公式（截断） | 内容宽 | 容器宽 | 残留溢出 | 无容差时的处理 |
|---|---|---|---|---|---|
| `/paired-data-independence` | `χ² = n(ad−bc)² / ((a+b)(c+d)(a+c)(b+d))` | 244.36px | 243px | **1.36px** | 等比缩放 0.9795 → 完全放下 |
| `/solid-section` | `P∈α∩β ⟹ α∩β=l, P∈l` | 252.72px | 251px | **0.86px** | 拆成 2 行 |
| `/derivative` | `f′(x₀) = lim(Δx→0) [f(x₀+Δx)−f(x₀)] / Δx` | 252.63px | 251px | **0.81px** | 拆成 2 行 |
| `/conic-param` | `⟹ { x = a cosθ, y = b sinθ (θ∈[0,2π)) }` | 243.70px | 243px | **0.70px** | 拆成 2 行 |
| `/parabola-archimedes` | `S△QAB = |y₁−y₂|³/8p = p²/sin³θ ≥ p²` | 251.52px | 251px | **0.52px** | 拆成 2 行 |

### 4.2 机制（元素级 DOM 比对，非推理）

以 `/derivative` 的 `f′(x₀) = …` 为例，同一条公式在两态下的形态：

| 状态 | `.katex` 节点 | 宽度 | 行数 | 溢出 |
|---|---|---|---|---|
| A2（有容差） | 1 个 | 252.63px | 单行 | **+0.81px** |
| B1b（无容差） | 2 个（`f′(x₀)` 43.91px ＋ `= lim…` 204.02px） | — | 两行 | −207 / −47px |

`/solid-section`、`/conic-param`、`/parabola-archimedes` 同理（都是 1 个 → 2 个节点）；`/paired-data-independence` 则是 1 个 → 1 个但 `scale=0.9795`。

**即**：容差把这些「只差 0.5~1.4px」的块级公式从拆行/缩放的路径上拦了下来，让它们以原尺寸渲染、右端被自身 `overflow-x-clip` 裁掉一条亚像素边。

### 4.3 视觉取证（4x 放大）

`scripts/shots/clip-1.36px-paired-data-independence.png`、`clip-0.81px-derivative.png`，取裁切边界 70px 宽区域、`deviceScaleFactor=4`。放大后右端笔画边缘与正常渲染**无法分辨** —— 1.36px 约为 14px 字号下 1/10 个字宽，且只发生在最外侧笔画。

**判定**：这不是功能性缺陷（无内容错乱、无重叠、无面板溢出、无水平滚动），但它**确实推翻了‘绝不裁切’这条硬不变量在 1~2px 量级上的保证**。是否接受，属于口径问题，见第八节。

## 五、项 ② 极短符号免缩放：零影响，属冗余保险

**判据**：只把这一个开关从 `responsive={!isShortSymbol}` 改为 `responsive={true}`（即关闭豁免），其余一切不动。

结果（B2 列）：73 路由上 `.katex` 总数、徽标三指标、value 类 `scaled/floor/clipped/minScale`、其他类三指标、残留溢出处数与最大值 —— **全部逐项完全相同**，连最小缩放比 **0.968**（`/nike-shifted`）都一致。

**两点结论**：

1. **不引入问题**：value 类 136 个元素在两态下都是裁切 0、触底 0；豁免条件（长度 ≤8、无四则运算、无 `\frac`/`\sqrt`）没有误伤任何需要缩放的表达式，`/nike-shifted` 那处长表达式仍照常缩放到 0.968。
2. **暂无收益**：2px 容差已经覆盖了这些微型符号的场景，该开关在真实页面上**命中的元素没有产生任何可观测差异**。判定为「防御性冗余」：留着无害（代价为 0），删掉也可（少一处判定 + 4 行注释的复杂度）。

> 复核通道可信度说明：本轮的「编辑 → 热更 → 全量复测」通道由 B1b 对照验证过（同一通道下触底 0 → 28，差异巨大），因此 B2 的“无差异”是真实结果，不是热更没生效。

## 七、实验 C：作用域化容差（已验证，**未落地**）

既然残留裁切的 5 处容器宽是 243~251px，而需要被容差保护的 28 处容器宽只有 6~15px，把容差**限制到微型容器**即可两头兼顾：

```diff
- if (containerWidth > 0 && contentWidth > containerWidth + 2) {
+ if (
+   containerWidth > 0 &&
+   contentWidth > containerWidth + (containerWidth < 32 ? 2 : 0)
+ ) {
```

| 徽标 缩放/触底/裁切 | 0/0/0 | **0/0/0** |
| value 类 触底/裁切 | 0/0 | **0/0** |
| 面板水平滚动 | 0 | **0** |

- **收益**：触底修复全部保留（28 → 0），同时 5 处残留裁切归零、`maxOver` 回到 0，`绝不裁切` 不变量重新成立。
- **代价**：核心组件 1 处判定改条件（3 行），`32px` 阈值取在 15px（实际最大微型容器）与 243px（真实块级容器）之间的宽阔空档里，边界不敏感。
- **风险**：`32px` 是经验阈值；若未来出现 32px 以下但确实需要缩放的容器，会重新出现 ≤2px 残留（与当前实现同级别，不会更差）。
