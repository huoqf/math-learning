# 右屏（MathPanel）公式渲染与组件接线审查报告

- 审查日期：2026-09-16
- 审查对象：`MathPanel` 及其子分区、`KatexFormula`、`latexUtils`，以及全库 73 条路由的右屏接线方式
- 审查方式：**运行时实测为主 + 全库静态链路分析为辅**（不修改任何业务代码）
  - 运行时：开发服务器（`vite` dev，端口 5199）+ Chromium 1600×900，逐路由测量右屏容器几何、每条 KaTeX 的可见包围盒、`transform` 缩放系数、最近的 `overflow` 裁切祖先
  - 静态：解析 `animId → builder → 返回字段` 与 `页面 → MathPanel 实际透传字段`，比对出「数据已生成但未上屏」的字段；再对全库 **1733 条 LaTeX 语料**跑拆行算法压力测试
- 结论：**右屏组件本身的分区结构、缩放与拆行主干是可用的，未发现右屏整体崩坏或大面积裁切**；但存在 2 类必须修的显示缺陷、1 类数据链路漏传缺陷，以及 4 项排版规范偏差。

## 二、问题详述与证据

### A. 右屏首部 `examAnchor` 徽标越界（P0，8 条路由）

**位置**：`src/components/UI/mathPanel/MathPanelHeader.tsx` 第 14–29 行

```tsx
<div className="flex items-center justify-between ...">
  <div className="flex items-center gap-2 min-w-0">
    <h3 className="font-bold ... truncate">{title}</h3>   {/* 标题可省略 */}
  </div>
  {examAnchor ? (
    <span className="text-[11px] px-2 py-0.5 ... shrink-0 flex items-center gap-1 ...">
      {examAnchor}                                        {/* 徽标：shrink-0 + 不换行 + 不省略 */}
    </span>
  ) : ...}
</div>
```

`shrink-0` 使徽标保持 `max-content` 宽度、既不收缩也不换行；右屏内容宽仅 **295px**，而 `examAnchor` 文案普遍 20~28 个汉字。实测越界结果：

| 路由 | 徽标宽度 | 越界量 | 是否使右屏容器水平溢出 |
|---|---|---|---|
| `/function-zero` | 340px | **+45px** | 是（`scrollWidth 352 > clientWidth 319`） |
| `/conic-line` | 320px | **+25px** | 是（`332 > 319`） |
| `/derivative-monotonicity` | 315px | **+20px** | 是（`327 > 319`） |
| `/conic-properties` | 307px | +12px | 否（被 `MathPanel` 根节点 `overflow-x-hidden` 裁掉） |
| `/conic-parabola` | 307px | +12px | 否 |
| `/solid-distance` | 307px | +12px | 否 |
| `/line-circle` | 306px | +11px | 否 |
| `/solid-parametric` | 301px | +6px | 否 |

示例文案：`人教A版必修第一册 · 函数与方程及二分法 (必考基础/解答通法)`、`高考大题第(2)问标杆 · 联立方程、判别式与韦达弦长三步走`。

> 也就是说：右屏**不会出现横向滚动条**（`overflow-x-hidden` 兜住了），代价是这 8 条路由的题型定位徽标被**静默截断**，用户看到的是半句话。这正是"超出边界 / 显示不完整"的典型表现，且是全部路由中唯一能测到右屏容器真的横向溢出的来源。

**修改建议**（三选一，推荐第 1 项）：
1. 徽标改为可收缩可省略：把 `shrink-0` 换成 `min-w-0 flex-1 justify-end` + `truncate`，并给 `title` 属性保留完整文案；标题侧同步改为 `max-w-[40%] truncate`。这样标题与徽标按比例分享 295px。
2. 徽标允许换行并在两行后省略：`whitespace-normal line-clamp-2`（`line-clamp` 需确认 Tailwind 4 版本已启用）。
3. 结构性方案：把 `examAnchor` 从首行徽标改为**头部下方的独立一行**（`text-[11px] leading-snug`，自然换行），首行只留标题。既彻底解决越界，也提升长文案可读性。
4. 数据侧兜底：把 `examAnchor` 文案统一压缩到 ≤ 16 个汉字（新增构建期断言），可从源头降低复发面。

### B. 公式被永久裁切（P0，3 条路由）

**判据**：取每条 KaTeX 最近的一个 `overflow-x ∈ {hidden, clip}` 祖先 A，比较 KaTeX 可见层 `.katex-html` 的右边界与 A 的内容右边界。实测越界即视为截断。

| 路由 | 模式 | 容器宽 | 内容自然宽 | 实际缩放 | 越界量 | 公式 |
|---|---|---|---|---|---|---|
| `/probability-markov` | inline | 221px | 647px | 0.65（触底线） | **+100px** | `P(A_{n+1}) = P(A_n)P(A_{n+1}\|A_n) + P(\bar{A_n})P(A_{n+1}\|\bar{A_n}) = 0.00p_n + 0.50(1-p_n) = p_{n+1} = (-0.50)p_n + 0.50` |
| `/solid-angle` | block | 243px | 593px | 0.55（触底线） | **+83px** | `\text{在 } \triangle ACD_1 \text{ 中利用余弦定理求 } \angle ACD_1，\text{几何平移法求得夹角与向量法完全一致}` |
| `/inequality-absolute` | inline | 249px | 412px | 0.65（触底线） | **+9px** | `\|x-a\| + \|x-b\| = \|x-a\| + \|b-x\| \ge \|(x-a)+(b-x)\| = \|a-b\|` |

**根因（三者同一）**：`src/components/UI/KatexFormula.tsx` 第 138–141 行

```ts
const needed = (containerWidth - 4) / contentWidth;
const minScale = canLineBreak ? HARD_MIN_SCALE : 0.65;   // 0.55 / 0.65
const nextScale = Math.max(minScale, needed);            // ← 缩放下限硬夹
```

- 当 `needed < 0.65`（行内）或 `< 0.55`（块级）时，缩放被夹在硬底线上，`contentWidth × minScale` 仍大于容器宽 → 公式两侧被裁。
- 三条公式都是**无法语义拆行**的：`/solid-angle` 是一条纯 `\text{}` 中文长句（内部 `，` 处于 `\text{}` 括号内、非顶层，拆行算法整条找不到断点）；`/probability-markov` 与 `/inequality-absolute` 是行内模式，而 `KatexFormula` 对 `mode="inline"` 默认 `allowLineBreak = false`，**行内公式严格禁止断行**（设计如此，见组件第 22–23 行注释）。
- 结果：inline 的绝对上限是「容器宽的 1/0.65 ≈ 1.54 倍」，block 是「1/0.55 ≈ 1.82 倍」；超过这个倍数且无法拆行的公式，无论如何都显示不全。

**量化风险面**：全库 1733 条 LaTeX 语料经拆行模拟后，**仍有 124 条单行宽度超阈值且完全没有拆行候选**（其中 `cases` / `array` / `aligned` 等环境 65 条，纯表达式 59 条）；另有 **30 条路由实测有公式被夹到硬底线**（`/probability-markov` 7 处、`/constant-double` 5 处、`/derivative-shift` 4 处……）。默认情景下只有 3 条真正露出截断，但**切换情景后暴露面会显著扩大**。

**修改建议**（按推荐顺序）：
1. **对长中文句子不要用 KaTeX**：`/solid-angle` 那条内容本质是中文叙述，应作为 `detail` 纯文本字段（走 `renderMixedLatex` 的纯文本通道）或改用普通 `<p>`，而不是塞进一个 `\text{}` 巨块。这是最省力且最根本的修法。
2. **行内模式增加「超限降级为块级」通道**：当 `needed < 0.65` 时，不再硬夹，而是切换到 `mode="block"` 渲染（必要时配合 `canLineBreak` 语义拆行）。把"不许断行"从硬约束降级为"优先不断行"，可一次性消灭 `/probability-markov`、`/inequality-absolute` 这类长推导链截断。
3. **硬底线改为可配置 + 越界告警**：保留 `HARD_MIN_SCALE`，但当 `needed < minScale` 时除缩放外**必须触发可见降级**（例如附加一行小字提示"公式较长，已缩小显示"）或上报开发期 `console.warn`，避免今后再出现静默截断。
4. **块级计算公式改入 `MathReasoningSection` 时拆成 `latexBlocks`**：该字段（`MathReasoningSection.tsx` 第 10 行 `latexBlocks?: string[]`）就是为此设计的"分块卡片"通道，长推导链按步拆成多块即可绕开拆行算法。
5. **补一条门禁**：把本次的截断检测（KaTeX 视觉右边界 vs 最近裁切祖先）固化为 e2e 断言，纳入 CI，可防回归。

### D. 拆行算法：标点兜底分支的两个缺陷（P1）

**位置**：`src/components/UI/latexUtils.ts` 第 455–486 行 `splitAtTopLevelPunctuation`

**D-1 把 `\;` 的分号当成顶层断点，产生非法 LaTeX（已单元级复现）**

候选扫描只看字符本身，不判断前一个字符是否为 `\`：

```ts
if (isTopLevel(state) && (latex[i] === "," || latex[i] === ";")) candidates.push(i);
```

实测输入 `\alpha \subset \beta, \; \alpha \cap \beta = l` 得到：

```
["\alpha \subset \beta, \", "\alpha \cap \beta = l"]
```

左行以**孤立反斜杠**结尾 —— 这是非法 LaTeX，KaTeX 会在 `throwOnError:false` 下把该片段渲染成错误文本/红色内容。当前页面未暴露该问题，是因为 `findOptimalSplit` 的优先级把 `splitAtTopLevelSpacing` 放在 `splitAtTopLevelPunctuation` 之前，多数情况已被正确拦截；但一旦出现"间距分支宽度校验不通过"的公式，就会落入该分支。全库语料模拟显示存在 30 条公式会走到这条路径。

**D-2 断点标点被直接删除，公式内容被改写**

```ts
const right = latex.slice(chosenIdx + 1).trim();   // ← 分隔符被丢弃
```

例如 `x_1 = 1, x_2 = 2, x_3 = 3` 会被拆成 `x_1 = 1, x_2` / `= 2, x_3 = 3`（原本 `x_2` 与 `= 2` 之间的逗号消失）。高中数学语境下这属于**内容级变更**，不是排版选择。

**修改建议**：
- 候选扫描增加反斜杠前缀判断：`const prev = latex[i-1]; if (prev === "\\") continue;`（或直接把 `\;` / `\,` / `\!` 等间距命令整体纳入"不可断"集合）。
- 断点标点保留在左行行尾（`right = latex.slice(chosenIdx + 1)` 改为 `left = latex.slice(0, chosenIdx + 1)`，右行从 `chosenIdx + 1` 起），符合"逗号留在上一行"的教材习惯。
- 更彻底的做法：与其在标点处断，不如让**标点分支只作为最后兜底**，并在其前面补一个"按 `\text{}`/中文短语边界断行"的分支，专门处理中文长句。

### E. 续行无悬挂缩进，与教材书写习惯不符（P1）

**位置**：`src/components/UI/KatexFormula.tsx` 第 196–200 行（多行块级容器）

```tsx
className={`... ${isMultiLine ? "flex flex-col items-start gap-2.5 text-left w-max min-w-0" : ...}`}
```

所有行都从同一左边界起排。而 `splitAtTopLevelEquals` / `splitAtTopLevelBinary` 的设计是**把 `=`、`+` 等符号放到续行行首**（这一点符合人教版教材习惯，是正确的），但教材里续行的 `=` 要**与首行的 `=` 纵向对齐**，或整体做悬挂缩进。当前实现下：

```
f(x) = a(x - h)² + k
= a x² - 2ahx + ah² + k      ← 续行 "=" 与首行开头 "f" 对齐，而非与首行 "=" 对齐
```

**修改建议**：多行渲染时，对"以关系符/运算符起头"的续行统一加悬挂缩进。可行做法：
- 在 `latexUtils` 拆行时返回断点的**左段有效宽度**，或在 `KatexFormula` 里用 `paddingLeft` 推一个近似值（例如首行首个顶层关系符之前的字符数 × 平均字宽）；
- 更稳妥：把多行改为单个 `\begin{aligned}` 环境交给 KaTeX 自己做对齐（`&=`），KaTeX 原生支持列对齐，且不依赖估算字宽。**这是最符合教材习惯的解法**，代价是需要把已拆分的行重新拼回 aligned 环境。

### F. `\frac → \dfrac` 全局强制升级（P2）

**位置**：`src/components/UI/latexUtils.ts` 第 495–526 行 `normalizeFractionRowSpacing`（对**所有**模式生效，含 `mode="inline"`）

- 行内公式（正文中的 `$…$`）按排版规范应用 `\frac`（textstyle），强制升为 `\dfrac` 会显著抬高行高，造成**正文行距忽大忽小**，与周围中文行不一致。
- 本次实测**竖向裁切 0 处**，说明当前没有出现"分式被 `overflow-hidden` 切掉分子/分母"的实际后果（`MathInvariantsSection.tsx` 第 105 行、`MathReasoningSection.tsx` 第 87 行都带 `overflow-hidden`），但这是**依赖容器恰好给足了高度**，属脆弱平衡。

**修改建议**：把升级范围限定为块级与多行环境（`mode === "block"` 或公式内含 `cases/aligned/array` 时），行内保持 `\frac`；若确有"行内也要满尺寸"的教学需求，改为页面级显式传入开关（如 `forceDisplayFraction`），而不是全局静默改写。

### G. 接线写法不统一（P2，C 类缺陷的根因）

全库 82 个渲染右屏的页面中：**29 个**已用整包透传 `{...mathData}`，**53 个**仍是逐项枚举。逐项枚举是 C 类漏传的唯一来源，且新增字段时必然再次遗漏。

**修改建议**：一次性全库统一为整包透传（可脚本化改写 + 逐页 diff 复核），并在 `.trae/rules/project_rules.md` 或 ESLint 自定义规则中固化"右屏必须整包透传"的约定。

## 五、附带发现（非本次审查范围，但影响验证）

**生产构建产物运行时崩溃**：执行 `vite build` 后 `vite preview` 打开任一深层路由，控制台报
`PageError: Cannot read properties of undefined (reading 'forwardRef')`，页面白屏（`body.textContent` 仅 10 字符）。
构建期同时有告警：`Circular chunk: vendor-misc -> vendor-react -> vendor-misc`。

这解释了 `e2e/formula-render.spec.ts` 为何依赖 `vite preview` 却难以稳定取到内容 —— 问题出在 `vite.config.ts` 的 `manualChunks` 把 `react` / `react-dom` 的依赖图切成了循环 chunk，导致某些 chunk 里 `React` 未定义。
**建议**：把 `vendor-react` 与 `vendor-misc` 的判定解耦（例如把 `react-dom/client`、`react/jsx-runtime`、`scheduler` 与 `react` 归入同一 chunk，并让其余依赖统一落到 `vendor-misc` 时排除对 `vendor-react` 的反向引用），或直接移除 `manualChunks` 中过细的切分。本次审查因此改用开发服务器完成（开发链路正常，无该问题）。
