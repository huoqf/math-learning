#### N1 ★★★ SSA 无解文案硬编码「a < h」，在 A ≥ 90° 时输出**错误的数值不等式**

- **位置**：`src/data/builders/triangleSolve.ts:271-272`（solveDetail / solveLatex）、`:332`（无解警示）
- **触发**：`/triangle-solve` → SSA → `angleA = 120°`、`b = 5`、`a = 5`（三者均在滑块量程内：angleA∈[15,150]，b∈[1,10]，a∈[0.5,12]）

**验算**（按 `src/math/triangleSolve.ts:205-291` 真实分支）：

```
h = b·sinA = 5·sin120° = 4.330127
diff = a² − h² = 25 − 18.75 = +6.25 > 1e-5   → 走 else 分支
sqrtDiff = 2.5，cosA = cos120° = −0.5
t₁ = b·cosA + sqrtDiff = −2.5 + 2.5 = 0      → 不满足 t > 1e-6，丢弃
t₂ = b·cosA − sqrtDiff = −5.0                → 丢弃
validTs.length = 0  ⇒  caseKind = "nonacute_no_solution"，solutionCount = 0
```

此时 **a = 5 > h = 4.33**，但 `:272` 输出：

```
a = 5.00 < h = 4.33 ⟹ ∅          ← 一条被 KaTeX 渲染的错误不等式
```

`:271` 说明写「底边 a 比临界高 h 还短」（事实相反），`:332` 警示写「当前对边 a < h (b·sinA)」（同样错）。三处同源，学生一眼看去会背下一条**假的判据**。

- **同类 A = 90°**：`angleA = 90°, b = 5, a = 5` → `diff = 0` 落 `|diff| ≤ 1e-5` 分支，`t = b·cos90° = 3.06e-16 ≤ 1e-6` → `nonacute_no_solution`；文案仍说「a < h」，实际 a = h = 5。
- **判定**：**确认错误**（`caseKind` 已正确区分，纯属文案未跟进）。
- **修法方向**：三条文案按 `caseKind` 分支：`nonacute_no_solution` 时写「A ≥ 90° 且 a ≤ b，A 已是最大角，无解」，latex 改为 `a = 5.00,\ b = 5.00 \implies \varnothing`，不再出现 `a < h`。
