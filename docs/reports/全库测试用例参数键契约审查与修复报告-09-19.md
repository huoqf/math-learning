## 二、问题机理

每个用例都是一次 `buildMathQuantities(animId, params, config)` 调用。三层之间**没有任何机制保证键名一致**：

| 层 | 事实源 | 说明 |
|---|---|---|
| 用例侧 | 测试文件里的 `params` 字面量 | 手写，`Record<string, number>` 类型，**任意键名都能通过类型检查** |
| 页面侧 | `src/data/registries/<topic>.ts` | 声明式参数唯一事实源（`paramMeta` / `defaultParams` / `Params` 接口） |
| builder 侧 | `src/data/builders/<topic>.ts` → `src/math/*` | 实际读取 `params.x`，读不到则回落默认值 |

⇒ 当用例写了页面不存在的键时，**不报错、不失败、不告警**：builder 读不到该键 → 回落默认值 → 断言（无 NaN）照旧通过。于是该用例**看起来在测一个边界场景，实际在测默认值**（本仓库既有命名："自洽型假测试"／"镜像形态"）。典型如 `{ magA: 3, magB: 4, thetaDeg: 60 }`：三条键里只有 `thetaDeg` 生效。

## 三、判据（三层交叉，逐层收紧）

| 层 | 判据 | 作用 |
|---|---|---|
| ① 全库存在性 | 键在整个 `src/` 中**既无 `key: ".."` / 接口字段声明，也无 `params.x` 读取** | **铁证**：任何代码路径都不可能读到它 ⇒ 该键必然无效（§三-A） |
| ② 页面声明域 | 键是否属于该 `animId` 目标页面的 registry 声明集 | 主判据：UI 永远产生不出这个键 ⇒ 用例不可达（§三-B） |
| ③ builder 读取 | builder / math 层是否真的读该键 | 排除"页面不声明但引擎注入"的合法键（§四） |

**实现要点（避免误报）**：`animId → registry` 的映射不是单点，而是分散在各 feature；且 `solidGeometry.ts` 一个文件内含 11 套 `xxxMeta: ParamMeta[]`（无单一 `paramMeta`），`lineEquation.ts` / `vectorPolarizationApollonius.ts` 又是 `Record<keyof XxxParams, …>` 形态（无 `key:` 字段）。故映射按"**调用 `buildMathQuantities("<animId>")` 的那个文件**"逐文件取具名 import 解析，并对被合并 `case` 的 animId 用 `mathQuantities.ts` 的 `switch → builder 文件` 反查兜底。

## 七、遗留与建议

1. **本报告未新增任何自动化护栏**。判据已成型（§三三层），但把它固化为测试需要一张 `animId → 页面 registry` 的运行时映射表（约 60 条），且解析 `solidGeometry.ts` 这类"一文件多 `xxxMeta`"时须按具名 import 精确取键。**是否立项由用户决定**（当前以本报告 + 五道门禁覆盖）。
2. **`params: Record<string, number>` 是本类问题的类型层缺口**：它接受任意键名，使 `tsc` 无法拦截。若要根治，需把用例的 `params` 收紧为"按 `animId` 联合的键集"，属类型层改造。
3. **`params: {}` 的语义**已在文件头部注释中声明（"使用该页声明域默认值"），后续若新增用例请沿用该写法而非重新引入未声明键。
4. 本次未触碰 `docs/reports/` 下 09-18 的两份历史报告（含同源的过期描述），历史归档不擅自修改。
