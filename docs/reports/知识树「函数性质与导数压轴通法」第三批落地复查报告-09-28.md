## 一、P0（数学/教学硬伤，必须修）

### P0-1　`/derivative-formulas`：`log` / `exp` 模式在 `paramA = 1.0` 时右屏整片 `Infinity` / `NaN`，且无任何警示

**证据（探针按注册表网格展开 `paramA ∈ {0.5,1,1.5,2,2.5,3,3.5,4}`，真实 builder 输出）**：

```
=== funcType=log paramA=1 *** 含 Infinity/NaN ***
Q[当前解析式]              $f(x) = \log_{1.0} x$
Q[切点坐标 P]              (1.5, Infinity)
Q[理论导数值 (切线斜率)]   Infinity
Q[平均变化率 (割线斜率)]   NaN
R2 ... $f(x_0) = Infinity$ ... $f(x_0 + \Delta x) - f(x_0) = NaN$ ...
R3 ... $f'(1.5) = Infinity \implies y - Infinity = Infinity(x - 1.5)$
（warnings：空）
```

```
=== funcType=exp paramA=1
Q[当前解析式]       $f(x) = 1.0^x$
Q[理论导数值]       0
T[导数公式全表]     $(a^x)' = a^x \ln a$   ← 同一屏
R1 ... $(a^x)' = a^x \ln a \quad (a > 0, a \neq 1)$   ← 同屏自相矛盾
```

**根因链**（比单点修复更重要）：
`registries/derivativeFormulas.ts` 的 `paramA` 是**与 `funcType` 无关的静态域**（`min 0.5 / max 4.0 / step 0.5` ⇒ 网格必含 `1.0`）
→ `math/derivativeFormulas.ts` 的 `exp` / `log` 分支只写了 `const a = paramA <= 0 ? 2 : paramA`，**没有 `a === 1` 守卫**
→ `Math.log(1) = 0` 作分母 ⇒ `Infinity`
→ `formatMathNumber` 把 `Number.isFinite` 检查放在最前，`Infinity`/`NaN` 被**原样当字符串输出**（不抛错、不变空）
→ builder 的 `warnings` 条件是 `if (res.warning)`，而 `res.warning` 只在「负幂次 x=0」「真数 ≤ 0」两处赋值 ⇒ **`a = 1` 静默通过**。

**为什么算 P0**：学生把底数滑块拖到 1.0（网格点，且 `handleTabChange` 把 `paramA` 设为 `Math.E` 后，1.5 与 1.0 都只是半格之遥）就会看到整屏 `Infinity`/`NaN`，与同屏定理直接冲突，且**没有任何提示告诉他"此处退化"**。

**建议方向（待用户确认，不擅自改）**：`paramA` 的 `min/max` 按 `funcType` 动态化（`log`/`exp` 排除 1.0，或 `marks` 标注 + 在 `a=1` 时置 `isValid:false` 并给 warning），而不是在调用点各自兜底。
