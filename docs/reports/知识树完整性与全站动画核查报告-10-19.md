## 3. P0：必须立刻改的 5 条数学/数据错误

> 每条均已回到源码复核，给出代入值。**这 5 条 `audit:strict` 全部 0 error**。

### P0-1 `/transform`：对数 + 自变量翻折的定义域写错（默认参数就错）

- **落点**：`src/data/builders/funcTransform.ts:93`
- **现象**：`log` 母函数 + `input` 翻折时，右屏写 `x ∈ (−∞, −|h|) ∪ (|h|, +∞)`。
- **实际函数**：`y = log₂|ω(x−h)|`（`src/math/transform.ts:87-94`），定义域是 **`x ≠ h`**。
- **验算**：默认 `h = 1` ⇒ 右屏写 `x∈(−∞,−1)∪(1,+∞)`；但 `x=0` 时 `log₂|0−1| = log₂1 = 0` 有定义，中屏曲线正穿过 `(0,0)`；取 `h=2` 则把 `x=1.5`（`log₂0.5=−1`）判成无定义。
- **修法**：改为 `x \neq h`。顺带把 `TransformAnimation.tsx:160` 硬编码的「对称轴 x = 0」改成动态 `x = h`（否则 h≠0 时设问与图形也不一致）。

### P0-2 `/nike-standard`：倒对勾（`a<0, b<0`）的定理方向写反

- **落点**：`src/data/builders/nike.ts:392`
- **现象**：定理 latex 无条件写 `f(x) ≥ 2√(ab)`，而同一张卡片的 `note`（`:395-397`）对 `a<0` 分支正确写着「取得**最大值**」⇒ 同卡自相矛盾。
- **可达性**：`registries/nike.ts` `a ∈ [−3,3]`、`b ∈ [−9,9]`，`a=b=−1` 是网格点。
- **验算**：`a=−1, b=−4, x=1` ⇒ `f(1) = −1−4 = −5`，`2√(ab) = 2√4 = 4`，面板断言 `−5 ≥ 4`（假）。
- **修法**：按 `a` 的正负分两支输出：`a>0: f ≥ 2√ab`（x>0）/ `a<0: f ≤ −2√ab`（x>0）。

### P0-3 `/nike-shifted`：`a<0` 时把最大值点写成 `y_min`

- **落点**：`src/data/builders/nike.ts:335`
- **现象**：推导链第 2 步 latex 恒为 `y_min = c + extVal`，而 detail 已按 `a` 分支（`:330-333`）。
- **验算**：`a=−1, b=−4, h=1, c=2` ⇒ `u=2, extVal=4`，面板给 `y_min = 2 + 4 = 6`；实际 `f(3) = −1·2 + 2 + (−4)/2 = −2`，是**最大值**。同页 `math/nike.ts:163-177` 算出的特征点是「最大值点 (3.00, −2.00)」⇒ 右屏两处自相矛盾。
- **修法**：`latex` 跟随 `a` 分支；`a<0` 时写 `y_{\max} = c − extVal`。

### P0-4 `/set-quantifiers`：探针读数把「钳制后的函数值」标成「未钳制点的函数值」

- **落点**：`src/data/builders/quantifiersBuilder.ts:143-147` × `src/math/quantifiers.ts:139-140`
- **现象**：`symbol: f(${probeX.toFixed(1)})`，`value: res.probeVal`；而 `probeVal = f(clampedProbeX)`，`clampedProbeX = clamp(probeX, left, right)`。
- **可达性**：`probeX ∈ [−5,5]`（`registries/quantifiers.ts:59-60`），`intMin/intMax` 可收到 `[0,1]` ⇒ 探针必然落在区间外。
- **验算**：`a=−2, b=2, k=1, h=0, v=1, probeX=−5` ⇒ 面板显示 `f(−5.0)=5.00`；真值 `f(−5)=26`，而 `5` 是 `f(−2)`。
- **连带**：中屏 `QuantifiersScene.tsx:118-119` 用未钳制的 `probeX` 定位、用钳制后的值定高 ⇒ 点会脱离曲线。
- **修法**：二选一——① 钳制 `probeX` 后再写标签（标签与值同源）；② 不钳制、直接把 `probeX` 限制在 `[left,right]`（滑杆联动）。

### P0-5 `/inequality-absolute`：平台临界 `m = ±|a−b|` 的解集被写成 `x ∈ ℝ`

- **落点**：`src/data/builders/inequalityAbsolute.ts:253-258`
- **现象**：`res.intersectionRoots.length === 1 ? x₀ : intervals.length === 0 ? ∅ : "x ∈ ℝ"`；而平台分支只填了 `intervals`、**没填** `intersectionRoots`（`src/math/inequalityAbsolute.ts:280-300`、`:325-345`）。
- **验算**：
  - `a=1, b=4, m=−3, "≤"` ⇒ 真解集 `(−∞,1]`（数学层 `intervals` 也正是 `[(−∞, a]]`），右屏写 **`x ∈ ℝ`**。
  - `a=1, b=4, m=3, "≥"` ⇒ 真解集 `[4,+∞)`，右屏写 **`x ∈ ℝ`**。
- **性质**：这是「数学层算对了、builder 渲染错了」的典型——两套口径在同一个返回值里打架。
- **修法**：平台分支同时写 `intersectionRoots`，或 builder 直接消费 `intervals` 生成解集文本（推荐后者，单源）。

## 4. 准 P0 与六类系统性 P1

### 4.1 准 P0-6 `/solid-rotation-body`：扫掠角只进图形、不进数值

- `RotationBodyAnimation.tsx:491-492` 把 `sweepAngleDeg` 传给 3D 场景（仅 `generation` 模式），而 `builders/solidRotationBody.ts` 全文 **0 命中** `sweepAngleDeg`。
- 后果：拖到 180° 时中屏是半圆柱，右屏仍报整周 `V=πr²h`、`S侧=2πrh`、展开圆心角 `(r/l)·360°`（体积/侧面积整整偏大 1 倍）；拖到 0° 图形为空、数值照旧。
- 修法：① builder 接收角度并按 `θ/360` 折算；或 ② 在 generation 模式下右屏追加 danger「以下数值为整周值，当前仅旋转 θ°」。**推荐 ②**——因为该滑块的语义是「演示生成过程」，强行折算会把教学重心从「旋转体是什么」拉到「扇形比例」。

## 6. 「能否有效辅助理解 + 高考提分」专项评估

**做得好的（可作范式）**：

1. **三屏分工清晰**：左屏「参数 + 设问 + 步骤导航」→ 中屏「几何对象 + 特征元素」→ 右屏「读数 + 定理 + 推导链 + 采分点」。这个骨架比多数教辅 App 完整。
2. **难点有真正的可视化**：`/trig-tangent` 把全部渐近线与全部对称中心 `(kπ/2,0)` 都画出来；`/solid-sphere-derivation` 的等高截面 `S₁=S₂=π(R²−h²)` 可逐高度对拍；`/sequence-arithmetic` 在负项时**主动收起**面积拼图并说明「代数恒等式仍成立」——这类「前提不成立就换说法」的处理是提分的关键。
3. **反例意识**：`/function-power` 的「指大图高」、`/probability-independence` 的「互斥必不独立」、`/derivative-inflection` 的 `x⁴` 不是拐点，都把易错点做成了可操作的反例。

**拖后腿的三件事**：

1. **推导链断层**（§4.6）：20 个数列子模式 + 7 个 builder 无步骤卡。学生看到的是「结论 + 一句口诀」，而不是「第一步设什么、第二步代什么、这一步几分」。这是「提分」与「看懂」的分水岭。
2. **采分点口径不统一**（§4.5）：5 套前缀、6 种分值、58 个页面无题位。学生无法把页面上的「3 分」映射到卷面上的「第 16 题 15 分」。
